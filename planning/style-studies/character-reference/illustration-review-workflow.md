# 成長イラストのレビューと進捗更新

表示ページは `illustration-review.html`、現在の進捗の正本は `illustration-review.json` の `entries[].currentAudit`。既存の `status` / `notes` とトップレベルの生成記録は過去の履歴なので上書きしない。

## 修正の単位

原則3枚ずつ。最初の代表画像は090（文字への気づき）、108（順番カード）、116（たかい、たかい）。同じキャラクターでも角度・姿勢・接点の違いを確認する。元の動作と子どもの優先順位を保持する。画像全体の一律色置換はしない。

## 画像を変更したら

1. `currentAudit.status` を「修正中」にし、着手する工程を更新する。
2. 人物・接点、動物の造形、背景、部位別配色の順で修正。対象外の領域に変化がないか確認する。
3. 保存後、原寸と実使用サイズで確認。`observation` に残課題、`stages` に実施状況、`history` に日付と実際の作業を記録する。
4. 目視した画像のSHA256を `imageSha256` に記録する。未確認の画像に新しいハッシュだけを付けて確認済みにしない。
5. 最終確認が残れば「再確認待ち」。完了の場合だけ `status` と `stages.finalReview` を「完了」にし、`verification` に検証方法・対象サイズ・残る制約を記録する。原寸確認済みなら `reviewLevel` を「原寸＋一覧確認」に更新。
6. JSONからHTMLを再生成する：

```sh
python3 planning/style-studies/character-reference/build-illustration-review.py
```

HTMLはJSONを埋め込まず静的に生成するためfile://でも一覧を表示できる。検索・絞り込みはページ内で動作する。画像URLは内容ハッシュでキャッシュを更新し、ファイル名にバージョン番号を付けない。

画像か基準のハッシュが変わると、再生成時に「要再点検」と表示される。基準変更後は全体を再照合してから `audit.referenceHashes` を更新する。ページを開いているだけでファイル変更を自動検知する機能ではない。

## 判定の範囲

2026-09-20の全120枚の確認は約490pxの一覧での一次点検。090・108・116は原寸でも確認。全画像の三面図との重ね合わせ、厳密な線幅・色・寸法測定、最終掲載サイズでの確認は未実施。「修正待ち」は現行基準へ移行する作業の状態で、全ての造形を不合格と断定する意味ではない。年齢・発達段階の区分は掲載文脈と照合してから髪や体格を決める。

今回対象はDevelopment一覧の137枠／120画像。未掲載の試作や別案は対象外。以前のHTMLは `illustration-review-history.html` に保存し、履歴を残す。

## ファイル名の運用

修正画像は既存の画像ファイルを同じ名前で更新する。refined等の接尾辞やバージョン番号は追加しない。履歴はGitとcurrentAudit.historyに残し、更新内容はrevisionAppliedに記録する。HTMLには現在の画像を1枚表示し、内容ハッシュのクエリでキャッシュを更新する。

## 表情の確認

小鳥の眉は造形調整時にも省略しない。正面は両眉、横顔は見える側の眉を確認する。目・眉・くちばしで場面に合う反応を表し、表情のために頭の輪郭を歪めない。喜び・集中・驚きなどを場面別に選び、目線が必要な場面では閉じ目にしない。

笑い目は通常の目に対して横幅・線の太さを誇張せず、小さく浅い弧で表す。眉との間隔を残し、大きな半円や太い山形にしない。
